# 前端界面设计规范

> **状态**：目标规范（normative）。第 1–5 节为规范原文，优先级最高；第 6 节以下是把规范落到代码的实施口径、当前差距与迁移清单。
>
> 当前代码仍基于旧的深色琥珀主题与系统字体，尚未按本规范迁移。文档、令牌或实现发生冲突时，以第 1–5 节为准。

---

## 1. 布局与信息

- 禁止大框套小框，禁止嵌套卡片与多余分割线。
- 禁止标语、副标题、次级标签和解释性描述文字。
- 用排版对齐和间距区分内容层级，不靠文字解释界面。

## 2. 视觉、色彩与留白

- 整体参考苹果官网极简风格。
- 色彩比例：90% 面积使用黑、白、灰中性色；10% 面积使用单一强调色标出核心操作或关键数据。
- 禁止渐变色、高饱和色、霓虹色和复杂阴影卡片。
- 字重与明度对比：标题加粗加深，正文变细变浅。
- 放大留白：组件内边距与外边距设为常规页面的 1.5 倍，宁可留空也不塞满。

## 3. 字体、栅格与图标

- 字体：全局使用 Geist 字体。
- 字号与字重：标题 18px 并加粗（字重 600 或 700）；正文使用 16px 或 14px，字重取常规（400）或中等（500）。
- 文字颜色：主文字用 `#181818`，次要文字用 `#6A6A6A`。
- 间距栅格：所有间距取 4px 的整数倍，不留例外。
- 圆角：按组件尺寸与层级，在 8px 到 40px 之间取值（小按钮用小圆角，大弹窗用大圆角）。
- 图标：使用 Reicon 图标库（https://reicon.dev/docs）。图标本体 18px，线条粗细 1.5px，放在 24px × 24px 的透明外框内。

## 4. 交互与桌面端菜单

- 按意图显示控件：平时隐藏次要操作按钮；当用户鼠标悬停、光标聚焦、滚动靠近或开始操作该区域时再显示。
- 桌面端多级菜单：同时实现开启延时、关闭延时、安全三角区。当鼠标从父菜单 A 移向子菜单 B 时，以当前鼠标坐标和子菜单 B 的上下边缘端点连成三角形区域；鼠标处于该三角形内时，保持子菜单 B 打开，暂缓切换到途经的其他菜单项。

## 5. 渲染验收

- 以浏览器真实视觉渲染结果为准，不以代码计算属性值为准。写完代码必须检查真实画面中的对齐、换行、留白与遮挡。

---

以下为实施口径。它把第 1–5 节翻译成令牌、组件与检查步骤，不改变规范本身的约束。

## 6. 实施口径

### 6.1 色彩

- **中性色承担 90% 的可见面积**：页面底色、表面、边框、图标与文字全部来自黑/白/灰阶。强调色只保留一个，用于核心操作或关键数据，面积不超过 10%。
- 亮色基准：主文字 `#181818`，次要文字 `#6A6A6A`。其余中性阶（背景、表面、边框、禁用态）需在令牌层补齐，并与暗色模式成对定义。
- 禁止：渐变、高饱和色、霓虹色、彩色阴影、复杂阴影卡片。阴影只允许极轻的中性投影，或直接不用阴影。
- 90/10 按视觉面积评估，不按令牌数量评估；强调色集中在核心操作或关键数据上，避免分散注意力。
- 状态的优先级：文字 > 字重 > 明度差 > 中性色形状；彩色状态色是否保留见第 10 节。

### 6.2 字体与排版

- 界面文字统一使用 Geist；等宽场景（代码、ID、路径）使用 Geist Mono。字体随应用打包，不依赖系统是否安装。
- 标题：18px，字重 600–700。正文：16px 或 14px，字重 400–500。
- 主文字 `#181818`，次要文字 `#6A6A6A`；不再使用全大写 eyebrow、副标题、解释性小字。
- 层级只靠字号、字重、明度、对齐与间距建立。删除一个说明文字前，先检查是否能用间距或对齐解决同一问题。

### 6.3 栅格、间距与留白

- 所有内边距、外边距、间隙、尺寸取 4px 的整数倍，不留例外。
- 留白在常规值基础上放大到 1.5 倍，结果取最近的 4px 倍数。常用映射：

| 常规 | 放大后 | 典型位置 |
| --- | --- | --- |
| 8px | 12px | 图标与文字、行内元素 |
| 16px | 24px | 组件内边距、表单行、卡片内间距 |
| 24px | 36px | 区块内边距、列表项间距 |
| 32px | 48px | 页面留白、区块间距 |

- 宁可留空，也不塞满：不通过增加文字、徽标或分割线来填补空间。
- 页面级留白优先使用 24–48px；内容列宽度可保持不变，但列内边距必须放大。

### 6.4 圆角

- 圆角只取 8px 到 40px 之间的 4px 倍数。建议刻度：8 / 12 / 16 / 24 / 32 / 40。
- 层级映射：小按钮与输入 8px；卡片与紧凑面板 12–16px；大面板与浮层 24px；弹窗与大容器 32–40px。
- 容器与内部控件保持一级圆角差，按组件尺寸与层级取值。
- 不再使用胶囊容器；状态圆点保持圆形。

### 6.5 图标

- 统一使用 Reicon。图标本体 18px，线宽 1.5px，置于 24×24px 透明外框内。
- 图标颜色继承当前文字色；禁止彩色图标、实心多色图标与自绘图标。
- 纯图标控件必须提供可访问名称；图标与文字同时出现时，图标不重复语义。
- 现有文本字形（`☰`、`✕`、`⚙`、`✓`、`▾`、`▸`、`↓`、`✦`、`!`、`↗`）全部替换为 Reicon；正文中的列表符号与任务勾选可用排版字符。

### 6.6 卡片、分隔与信息层级

- 表面只允许一层：页面 → 区块 → 内容。禁止 `Surface` 套 `Surface`、卡片内再放卡片。
- 删除可被留白替代的分割线；页头/页脚的结构边框也需逐一审查，能去掉就改为间距。
- 不写标语、副标题、次级标签、解释性描述。标题 + 内容即为完整结构。
- 列表、表单、工具结果通过水平对齐、垂直节奏和 4px 栅格分组，不通过加框或加线分组。
- 必要的功能反馈（校验错误、危险确认）是否也适用「禁止解释性描述」，见第 10 节。

### 6.7 控件显隐

- 次要操作默认隐藏；满足以下任一条件时显示：鼠标悬停所在区域、键盘焦点进入、滚动接近该区域、该操作已开始。
- 显隐不能造成布局位移：优先使用覆盖式浮出，或为控件预留固定占位。
- 键盘用户必须能通过 Tab 让隐藏控件显形；紧凑/触控环境没有 hover，需改为常显或由显式操作展开（见第 10 节）。
- 主要操作与关键数据始终可见，不参与隐藏。

### 6.8 桌面端多级菜单

- 新建菜单组件，不沿用当前单层 `OptionSelect` 的交互模型。
- 必须实现三件事：开启延时、关闭延时、安全三角区。
- 安全三角区算法：指针离开父项 A 时记录当前坐标，与子菜单 B 的上下边缘端点构成三角形；指针位于该三角形内时保持 B 打开，不切换到途经的其他菜单项；指针离开三角形后才按目标项切换。
- 菜单本身仍是单层表面：24–32px 圆角、无嵌套、无多余分割线、无解释性文字。
- 延时时长、动画时长规范未给定，集中定义在组件层，便于统一调整。

### 6.9 渲染验收

- 以真实浏览器渲染为准；不得只检查 computed style、类名或代码逻辑。
- 每次改完界面至少检查：
  - 亮色与暗色；
  - 常规宽度与紧凑宽度；
  - hover、focus、滚动接近三种显隐触发；
  - 长标题、长路径、长错误信息的换行与截断；
  - 浮层与滚动区域的遮挡关系；
  - 多级菜单的开启/关闭延时与安全三角区。
- 用截图核对：4px 对齐、留白是否放大、是否存在嵌套卡片、是否有可删除的分割线、强调色面积是否超过 10%。
- 出现换行、对齐或遮挡问题时修布局，不靠增加说明文字掩盖。

## 7. 当前实现差距与迁移清单

| 项目 | 现状 | 目标 | 处理位置 |
| --- | --- | --- | --- |
| 主题 | 深色暖琥珀 + 暖米色亮色主题 | 中性色 90% + 单一强调色 | `nsh.json` 主题令牌 |
| 字体 | `ui-sans-serif` / `ui-monospace` | Geist / Geist Mono | `nsh.json` 字体令牌 + 字体资源 |
| 文字色 | `#f0eadf` / `#28231c` 等暖色阶 | 亮色 `#181818` / `#6A6A6A`；暗色待定 | `nsh.json` 中性阶 |
| 强调色 | 琥珀金广泛用于按钮、徽标、选中、图标 | 单一强调色，面积 ≤10% | `src/theme.ts` + 组件 |
| 间距 | 4px 基准，但普遍使用 12–20px 内边距 | 常规值 ×1.5，统一 4px 倍数 | `src/components/**` |
| 圆角 | 6 / 8 / 12 / 16px | 8–40px | `nsh.json` 圆角令牌 |
| 图标 | 文本字形 | Reicon 18px / 1.5px / 24px 外框 | `src/components/**` |
| 卡片 | 设置分组内嵌套来源卡、目录选择器、警告块；工具卡内再套代码块 | 单层表面 | `SettingsGroup`、`SourceCard`、`ToolCard` 等 |
| 分隔线 | 检查器每个分区、顶栏/底栏、设置编辑器底栏均有线 | 仅在必要时保留 | `Inspector`、`Composer`、`Sidebar`、`Settings` |
| 副标题/说明 | 侧栏品牌副标题、Workspace eyebrow、顶栏元信息、检查器副标题、设置分组描述、字段描述、空状态说明 | 全部删除或改为结构性标签 | 见下方逐项 |
| 控件显隐 | 复制、刷新、删除、重置常显 | hover / focus / 滚动接近时显示 | `CopyButton`、`CenterHeader`、Provider 操作组 |
| 多级菜单 | 仅单层 `OptionSelect` | 延时 + 关闭延时 + 安全三角区 | 新建菜单组件 |
| 验收 | `npm run check` / `build` 为主 | 真实浏览器截图验收 | 第 6.9 节流程 |

逐项说明：

1. **令牌**：`nsh.json` 的亮/暗两套值整体重定；`src/theme.ts` 的 `textClasses`、`surfaceClasses`、`markdownClasses` 需要随新中性阶重写。`eyebrow`、`small`、`dim` 这些层级在删除说明文字后可能失去用途。
2. **强调色**：当前 `primary`、`warning`、徽标、选中态、品牌符号同时使用琥珀金，违反单一强调色与 10% 面积。迁移时先确定唯一强调色，再收紧所有使用点。
3. **卡片去嵌套**：`SettingsGroup` 内的来源列表、`CatalogPicker` 的 `Surface inset`、编辑器内的警告 `Surface`、工具卡内的代码详情，都需要合并为同一层表面或直接去底色去边框。
4. **删线**：`Inspector` 的 `Divider`、`Composer` 的 `border-t`、`Sidebar` 底部分隔、设置编辑器底栏 `border-t`、各页头 `border-b` 逐一改为留白；保留前必须能说明它承载的是结构而非装饰。
5. **删文案**：侧栏 `native shell workbench`、`Workspace` eyebrow、顶栏 `Embedded Forge Core · NSH web shell`、检查器 `Connection, workspace and run state`、设置页每个分组的描述、每个 `Field` 的 description、空状态说明、审批卡 `Forge is paused until you decide.` 等，按第 1 节删除。
6. **显隐**：复制按钮从始终可见改为消息悬停/聚焦时出现；刷新、删除、重置放入所属区域的悬停操作组；状态与主要操作保持常显。
7. **菜单**：`OptionSelect` 目前是单层弹层，没有多级结构与安全三角区；需要新增独立菜单组件，并把设置、模型选择等入口迁移过去。
8. **Markdown**：提示块、行内代码、链接当前使用 info/success/primary/warning/danger 多色，需按中性色 + 单一强调色重排；状态色去留见第 10 节。
9. **响应式**：紧凑态没有 hover，隐藏的次要操作必须常显或通过显式入口展开；不能直接复用桌面端显隐逻辑。

## 8. 可访问性底线

极简和隐藏控件不得削弱可访问性：

- 所有交互元素保留可见焦点环（2px，偏移 2px）。
- 纯图标按钮、下拉、输入框提供可访问名称；隐藏控件在键盘聚焦时必须显形。
- 状态不能只靠颜色：至少同时使用文字、字重或形状。
- 文本可选、可复制；错误信息使用 `role="alert"`。
- 动效遵循 `prefers-reduced-motion`。
- 触控目标不小于 32px；主要操作不小于 36px。

## 9. 建议落地顺序

1. 重定 `nsh.json` 中性阶、强调色、圆角；接入 Geist。
2. 重写 `src/theme.ts` 的排版与表面类，删除 eyebrow/副标题体系。
3. 去嵌套卡片、删分割线、放大留白。
4. 改造次要操作显隐。
5. 新建多级菜单组件（延时 + 安全三角区）。
6. 按第 6.9 节做真实浏览器截图验收。

## 10. 待确认事项

规范未覆盖、需要产品决策的点：

1. **暗色模式**：`#181818` / `#6A6A6A` 是亮色基准；暗色主/次文字值、表面阶与强调色尚未给出。
2. **状态色**：90% 中性 + 10% 单一强调是否意味着取消 info/success/warning/danger 彩色？错误、警告如何在不使用彩色的前提下保持可辨识？
3. **功能文案边界**：校验错误、危险确认、空状态、表单帮助文字，是否也属于「禁止解释性描述」？本规范的执行口径默认保留必要功能反馈。
4. **强调色选择**：沿用现有琥珀金，还是换成新的单一强调色？
5. **触控/紧凑态**：hover 显隐在无鼠标环境下的替代方式（常显、长按、更多菜单）尚未定义。
6. **圆角与胶囊**：现有徽标、状态胶囊是否必须改为 8–12px 圆角？规范给出的 8–40px 区间不包含全圆角。
7. **菜单延时**：开启/关闭延时的具体毫秒数未给定，需在组件层确定。
